# AMANAH / GHSCL Objection-Handling Book

**Version:** 1.0.0  
**Control date:** 2026-10-03  
**Use:** China mission, partner meetings, executive briefings, buyer/importer discussions  
**Method:** answer with architecture and evidence; do not overclaim.

| Objection / question | Controlled response |
|---|---|
| “Are you replacing JAKIM?” | No. The topology is **AHTE ⇄ Direct JAKIM API ⇄ JAKIM**. AHTE prepares, validates and exchanges evidence; competent-authority decisions remain with authorised humans. |
| “Does AI certify Halal?” | No. AI supports D0–D2 analysis and configured D4 holds. D5/D6 authority/legal decisions are reserved. |
| “Does blockchain make something Halal?” | No. Cryptographic controls can help prove record integrity and provenance. Integrity is not truth, certification or legal release. |
| “If the lab says pork DNA not detected, is the product Halal?” | No. **NOT_DETECTED ≠ HALAL.** A laboratory result is one evidence object within the wider assurance and authority process. |
| “Why do we need AHTE if we already have ERP/QMS/WMS?” | AHTE is not intended to replace those systems. It connects their evidence to applicability, controls, custody, audit, exceptions and trust states across organisations. |
| “Why should a manufacturer share sensitive data?” | Cross-border default is minimum-necessary, purpose-bound disclosure. Access is role-, organisation-, purpose- and jurisdiction-scoped. |
| “Can the system release a shipment automatically?” | Operational rules may automate configured holds or internal actions, but authority/customs/sovereign release remains with the responsible human/authority. |
| “Is the JAKIM API live now?” | The direct integration point is part of the platform architecture. Production activation requires the authorised JAKIM technical specification, scopes, credentials and UAT; internal/sandbox responses are not represented as official authority responses. |
| “Why Malaysia if goods go China → GCC?” | The physical corridor is China → GCC direct. Malaysia is the governance/assurance/authority-connectivity plane unless a separate physical movement is explicitly scoped. |
| “What does GHSCL actually operate?” | The international operating/digital-infrastructure layer: corridor coordination, AMANAH platform, AHTE evidence/trust operations and 24/7 Command Center functions, subject to counterparty and authority boundaries. |
| “What is PHC’s role?” | The project architecture records PHC as the Perak State Government halal-industry GLC. Exact production/authority scope must follow verified mandate and competent-authority arrangements. |
| “What does Sinotrans do?” | Proposed operating scope covers warehouse and end-to-end logistics custody, telemetry and shipment events. Exact sites/lanes/systems require partner validation and production authorization. |
| “Do you replace Sinotrans systems?” | No. The architecture integrates WMS/TMS/Y2T/MIS/EDI/IoT where authorized. |
| “Can the platform prove the real-world event is true just because it has a hash?” | No. A hash proves integrity of the recorded content, not the truth of the event. Provenance, actor identity, custody and review remain necessary. |
| “How do corrections work?” | Evidence is append-only. Corrections are represented by supersession/version relationships rather than silent overwrite. |
| “What happens when evidence breaks?” | The exception engine can place an object in HOLD/QUARANTINE/DISPUTED/CORRECTIVE-ACTION, determine blast radius, route ownership and require re-verification. |
| “Can one good trust score compensate for a failed critical control?” | No. Critical controls and authority gates are non-compensatory. The system keeps authority, trust, operational, customs and finance states separate. |
| “Is Shipment 001 already real?” | No. It remains **NOT-INSTANTIATED** until there is real product, buyer/importer, batch, evidence, custody and destination data. |
| “Can you guarantee GCC market access?” | No. Destination authority/importer requirements and commercial acceptance remain independently owned. |
| “Can you guarantee financing?” | No. AHTE can assemble purpose-bound evidence. Credit, financing, Takaful and Shariah/legal approvals remain with the relevant provider. |
| “Are your prices final?” | Only executed commercial schedules are binding. Unvalidated figures are commercial proposals or assumptions requiring validation. |
| “Why smart glasses?” | They can make site observations more attributable by binding auditor/device/object/evidence context. They do not replace the auditor or authority. |
| “What if connectivity fails during an audit?” | The smart-audit model supports controlled offline capture, local hashing/signing where configured, then sequence/signature reconciliation on sync. Conflicts remain visible. |
| “Who owns an exception?” | Every exception requires an assigned owner, severity, affected objects, action, due date and closure evidence. |
| “What is the Command Center?” | A 24/7 operational view for evidence integrity, manufacturing, laboratory, audit, custody, logistics, ports, destination events, predictive risk and exception response. Operator permissions remain distinct. |
| “Can JAKIM and GHSCL see the same things?” | Not necessarily. Roles and permissions are distinct. Authority-side and operator-side monitoring do not imply identical access. |
| “What stops fake production data?” | Identity, source binding, signatures/hashes, provenance, audit tests, anomaly/contradiction detection and human review reduce risk; technology alone cannot guarantee truth. |
| “Can the system work before every partner API is live?” | Yes. Interfaces and adapters are built against controlled contracts with connector states UNCONFIGURED/DEVELOPMENT/SANDBOX/PENDING_AUTHORIZATION/PRODUCTION. External activation should not require architectural redesign. |

## Handling discipline

1. Answer only the question asked.
2. Separate **verified fact**, **implemented capability**, **project-defined capability**, **planned integration**, **commercial proposal**, and **assumption requiring validation**.
3. Never invent a partner commitment, authority response, buyer order, shipment event or certificate.
4. Convert unresolved objections into an owner + evidence request + date.
